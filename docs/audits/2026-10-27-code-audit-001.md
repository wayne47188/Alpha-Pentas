## Reliability and security interpretation

The issuance algorithm is intentionally fail-closed:

1. PostgreSQL performs a short atomic lease reservation.
2. CA signing occurs outside any SQL transaction or row lock.
3. Finalization obtains a short lock and verifies the lease owner/fencing token before writing the certificate and activating the Agent.
4. A stale signer cannot commit after lease takeover.
5. A lost Manager DB pool cannot commit the completed signature; after the lease expires, another Manager/DB pool can take over and produce exactly one durable certificate.
6. Only certificates committed in Manager state and still active/unrevoked are accepted by identity policy.
7. The Agent gRPC interceptor binds each stream to the TLS-authenticated SPIFFE identity, requires a matching project scope, and terminates an established stream after authoritative revocation/suspension/expiry.

The operator API is also fail-closed:

- Health/readiness and operator API use separate listeners.
- Operator API requires `tls.RequireAndVerifyClientCert`.
- Caller identity comes from a verified certificate fingerprint mapped in PostgreSQL, never from request headers or JSON.
- Authorization binds Principal, tenant, project and action.
- Revoked operator certificates are rejected on the next request even on an existing TLS transport.
- Denials are persisted to PostgreSQL.
