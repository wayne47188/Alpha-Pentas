# P1 Certificate Issuance — Persistence Prototype

Added `ValidatedClaim` to reject invalid / SAN-spoofing CSR requests **before** consuming tokens, and `IssueClaim` to bind a pending claim's stored CSR digest to a manager-assigned Agent identity.

The issuer locks the claim row, checks exact CSR digest, signs a client certificate with the separate Identity Issuer, stores public certificate bytes + fingerprint + serial, updates claim to `issued` and Agent to `active`, all before committing. Successful request replay with the same CSR returns the stored public certificate while certificate remains unrevoked.

This narrows the prior half-enrollment window, but is **not yet an authenticated or network-exposed enrollment flow**. Caller authentication, project authorization, trusted receipt possession, DB driver provisioning, live PostgreSQL integration tests and CA rotation/revocation checks must precede release. Claim IDs alone are not authorization. No Agent private keys are stored or generated by the manager.

Signer failure rolls back DB changes. A process failure after cryptographic signing but before transaction commit can result in a new serial on retry; only the committed certificate is authoritative. A production issuer should use a signing queue / short locked reservation and bounded signing deadlines to avoid holding long DB transactions.

Migration sequence: 0001, 0002, 0003. Certificates issued under this prototype must not be trusted by a production mTLS endpoint until revocation, authorization and tenant policy validation are in place.
